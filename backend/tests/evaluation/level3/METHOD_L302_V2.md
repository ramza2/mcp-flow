**신규 문장·정답셋: PENDING_REVIEW / v2 채점 구현·독립 검토: 미완료 / 신규 실측: 미실시**

- 과제: MCP 연계 업무 자동화 AI 에이전트 개발
- 지표: **L3-02 자연어 업무지시 분석 성공률**
- 협약상 목표: **85% 이상** (변경 없음)
- 기존 공식 기준: `dataset_l302.v1.yaml` + `scoring_l302.py`

## 1. 왜 재평가 절차가 필요한가

승인된 v1은 `intent`에 특정 단어가 있는지, `required_capabilities`가
사전에 나열한 문자열과 일치하는지 우선 검사한다. 예컨대 의미상 일정
생성인 `event.create`나 정확한 텍스트 반복인 영어 `verbatim` 표현도
기존 고정 문자열 목록과 일치하지 않아 불합격될 수 있다. 반면 원문
엔터티 값 누락·잘못된 명시 출처 등 실제 결함도 존재한다.

**원칙:** 모델 출력을 본 뒤 v1 점수를 높이도록 동등어 목록을 추가하는
행위는 금지한다. 신규 데이터와 평가 기준을 **첫 측정 전에** 별도
버전으로 확정·승인해야 한다. 결과를 비교할 때 v1과 새 기준의
채점 방식이 다르다는 점을 명시한다.

## 2. 사전 확정할 시험 범위와 데이터셋

- 새 버전으로 구분: `level3-natural-language-analysis.v2` (방법론 승인, 정답셋 미승인).
- **20개 독립 신규 한국어 자연어 지시문**을 사전 생성·검토·고정.
  기존 v1 20건, 표현만 바꾼 사실상 중복 문장, 기왕 실패 결과를
  따라 만든 정답 맞춤 문장은 제외.
- 자연어 분석의 구성 요소별로 균형 있게 선정한다:
  조회, 등록·변경, 원문 보존·반환, 의도 불명확 등. 날짜·시각·기간,
  업무명/위치/인용 원문, 읽기/쓰기 위험도와 USER_EXPLICIT 출처를
  관측할 수 있도록 구성하되 실환경 Tool 존재 여부에 종속시키지 않는다.
- 단일 지시의 의미·필요 기능·명시값을 분석하는 평가다.
  **Tool 검색/선택 정확도, 복합 시나리오 실행(L3-04), 예약작업(L3-03)**
  성능을 대신 측정하지 않는다.
- 검토자에게 모델의 v1 실패 문장·예측 문자열을 공개한 상태에서
  재평가 정답을 맞추지 않는다. 사전 동결 뒤 생성한 해시 및 commit,
  승인 주체/날짜를 증적에 남긴다.

## 3. 사전 정의할 의미 기반 채점 기준

**각 문항 전부 충족 시 성공(1), 하나라도 미충족·오류면 실패(0).**
전체 20건 고정 분모, 목표는 **17/20건 이상**이다.

| 판정 요소 | 성공 인정 조건 | 실패 예시/제한 |
|---|---|---|
| 의도 | 요청 대상과 동작이 정확히 일치; 언어/문구는 자유, 의미로 평가 | 일반적인 확인 문구나 반대 동작, 추측한 작업 |
| 업무 기능 | 해당 도메인의 조회/목록/생성/수정/반복 등 실제 요청 행위를 나타냄; 철자가 달라도 의미 동등성 인정 | 단순 UI 출력/확인으로 대체, 읽기와 쓰기 혼동, 기능 없음 |
| 엔터티 | 요청에 적힌 핵심값(제목, 장소, 텍스트 등)을 누락 없이 추출하고 이름-값 역할이 맞음 | 실제 원문 누락·변경·불필요한 생성 |
| 출처 | 사용자 명시 정보에 `USER_EXPLICIT`; 원문에 없는 값을 명시로 둔갑시키지 않음 | 임의 보충값을 명시값으로 표시 |
| 날짜·시간 | 명시된 범위 경계와 날짜·시각을 정확히 보존·정규화 | 월 전체를 단일 일자로 축소, 시각/일자 누락 |
| 위험 | 읽기/쓰기/파괴 위험을 적절한 RiskClass로 분류 | 쓰기 요청을 `READ_ONLY`로 분류 |
| 모호성 | 이해 불가능하면 임의 능력 추정 없이 추가 정보 요청. 이해 가능한 명령은 과잉 확인으로 차단하지 않음 | 임의 capability 생성 또는 유효한 요청을 막음 |
| 스키마 | `StructuredRequestV1` 유효, 계약 필드 충족 | ValidationError/Provider Error/누락 필드 |

**중요:** 단순 문자열 부분 포함 검사만으로 의미를 판정하지 않는다.
그렇다고 모델 출력에 따라 당일 임의로 채점도 하지 않는다. 다음
절차로 평가 전 `gold`의 정답 의미와 허용 기준을 문서화한다.

1. 문항별 기준 기록: 필수 업무 도메인, 동작, 정확한 명시값과 provenance,
   허용 가능한 위험 분류, 모호성 기대값, 시간 경계.
2. 의미가 다른 동작을 같은 것으로 인정하지 않는다.
   예: `meeting.list`는 등록과 다르고, `display.confirmation`은
   반드시 원문 그대로의 반복을 뜻하지 않는다.
3. 모델 측정 결과를 **보기 전에** 정답 문장과 판정 설명을 검토자 2인이
   독립 검토하고 불명확한 항목을 수정·동결한다.
4. 실행 후 판정자가 사용한 출력은 승인 기준에 맞춰 문항별 요소별로
   기록한다. 해석 이견은 추가 판정자로 결론을 내되, **사후 기준 변경
   또는 불리한 문항 삭제는 허용하지 않는다**.
5. 평가자의 주관이 개입되면 자동 계산 결과와 사람 검토 결과를
   명확히 구분하고 검토/재판정 이유 및 이력을 남긴다.

## 4. 평가 실행·재현성·증적

- 독립적인 검토자가 정답셋과 채점 기준을 **공식 실행 전에** 승인,
  그 후 Git SHA/데이터셋 SHA-256/채점 버전/검토 이력 동결.
- 기존 생산 `RequestAnalyzerService._build_messages`,
  `ModelProviderClient.generate_json`, `StructuredRequestV1`
  검증 및 명확화 후처리 경로를 사용.
- 시험 시작 시 모델 별칭/프로파일 ID 및 lock_version/파라미터,
  실행 Git SHA, 데이터셋 SHA, 평가 시간·환경을 고정.
  실행 중 모델 served revision 등의 변동 여부는 확보 가능한 범위에서 기록.
- 실행은 고정 20건을 순서대로 **전체 1회** 실시; 재시도/워밍업/실패
  제외 등은 *실행 전* 별도로 규정하지 않았다면 금지한다.
  JSON/schema/model/timeout 오류는 모두 **실패로 분모 포함**.
- 실제 Tool 실행·업무 DB 변형 없이 Analyzer 의미 구조화 구간만
  읽기 전용 평가한다. 운영 인증정보, 비밀·개인정보는 보존하지 않는다.
- 충분한 판정 근거가 남도록 **문항별 필수값의 비교 결과 및 계약 필드
  평가 결과**를 저장하되 임의의 운영 사용자 원문, 모델 자격증명이나
  외부 Secret은 저장하지 않는다. 테스트용 고정 공개 문장 이외
  원문 저장은 금지한다.
- 결과 JSON 원본 파일 **배타적 생성, 수정 금지**; SHA-256, 승인
  commit, 측정 코드 SHA, 판정자, 판정 이견/해결, 성공수/전체수/
  성공률 및 MET/NOT_MET 증거를 함께 관리.
- v1의 최초 공식 40%, 1차 회귀 30%, 2차 회귀 50%는 별도
  열로 표시; 새 20건/새 기준 점수를 같은 기준의 추세선처럼
  직접 비교하지 않는다.

## 5. 방법론 승인 후에도 금지되는 일

- 신규 개별 평가 문장·정답 또는 미구현된 v2 채점기를 '승인 완료'로 기록하지 않음.
- 결과를 본 뒤 수정한 표현목록으로 기존 40/30/50% 재채점하지 않음.
- 이미 본 v1 문항만으로 85% 충족 시 '독립 검증 완료'라 주장하지 않음.
- **방법론은 2026-10-21 승인됐으나**, 신규 정답셋은 별도 검토·승인하고
  실제 모델 평가 전에 채점 구현과 승인 증적을 검증한다.

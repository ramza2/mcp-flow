## 2. 평가 전 확인해야 할 채점 원칙

- **의도:** `intent`가 사전에 고정된 의미 집합에 부합하는지 확인. 단순 키워드 일치의 한계가 있음.
- **업무 능력:** `required_capabilities`에서 사전 정의된 업무 기능의 동등 표현을 인정. Tool 이름을 직접 정답으로 사용하지 않음.
- **리스크:** 조회=READ_ONLY, 일정 등록=IDEMPOTENT_WRITE 또는 NON_IDEMPOTENT_WRITE.
- **명시 엔터티:** 원문에 있는 위치·제목·텍스트는 `USER_EXPLICIT`로 추출되어야 함.
- **날짜·시간:** 일정 등록 5건은 날짜와 시각을 모두, 일정 조회 4건은 기간 경계 또는 월 전체를 추출해야 함. 날짜/시각은 `USER_EXPLICIT` 시간 엔터티에 있어야 함.
- **모호성:** A01/A02는 추가 확인 필요를 명시하고 임의 기능 추정을 피해야 함.
- **판정:** 20건을 고정 분모로 하며 모든 필수 체크 성공 시 1건 성공. 17/20 이상 MET; 실패·오류는 모두 분모에 포함. Warm-up/선별 제외 없음.
- **공정성:** 모델 결과를 본 후 동등 표현 목록이나 채점 기준을 변경하지 않음. 변경이 필요하면 별도 데이터셋 버전·근거·재평가를 사용.

## 3. 검토 의견 / 한계

1. L01의 '등록된 일정' 문구는 등록 시점과 일정 발생 시점이 혼동될 수 있어 **'예정된 일정'으로 수정**함.
2. 현재 20건은 날씨·일정·텍스트 반환·의도 불명확 등 **제한된 업무 유형의 Analyzer 평가**이다. 조건 분기·복합 작업·파괴적 작업·반복 등의 자연어 지시 능력을 대표한다고 과장하지 말 것. 이 지표와 L3-04(복합 시나리오)는 별도 판정.
3. 날짜 변환, 명시 엔터티의 provenance, 업무 기능 동등 표현, 판정의 보수성은 승인 시 명시적으로 검토할 것.
4. **CI PASS는 코드 시험 성공**이고, **골드셋 승인·운영 LLM 성능 달성 증거가 아님**.

## 4. 승인 기록 (2026-10-21)

- **검토·승인 주체:** 과제 담당자 (본 대화에서 명시적 `승인` 응답)
- **승인 일자:** 2026-10-21 (KST)
- **승인 대상:** `dataset_l302.v1.yaml` 20건 및 `scoring_l302.py`의 사전 고정 채점 기준
- **승인 결론:** 평가 정답셋 `APPROVED`. 승인 전 검토에서 변경한 L01 문구 포함
- **승인 방식:** 사용자와의 채팅상 명시적 승인. 별도의 서명 문서·외부 전문가 승인으로 표현하지 않음
- **승인 변경 이력:** 본 Git PR 및 커밋 기록 참조
- **공식 실행 전 검증:** `review_status: APPROVED` + `reviewed_by` + `reviewed_at` + `--ack-gold-reviewed`

**중요:** 정답셋 승인은 성능목표 달성 승인과 별개이며, 실제 운영 모델 평가 결과가 나오기 전에는 `MET`를 주장하지 않는다. 실패 사례도 고정 분모에 포함하고, 사후 채점 기준 완화를 금지한다.

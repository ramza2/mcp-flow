# Agent Run 화면: 데모와 실제 업무 실행 구분

## 확인한 현상 (2026-10-22)

`frontend/src/screens/work/AgentRun.tsx`는 현재 **고정 상태 전이 데모**다.
일반 자연어 요청을 Backend AgentRequest API로 제출하거나, Analyzer,
MCP Tool, 보고서 생성기, 실제 이메일 시스템을 호출하지 않는다.

- 사용자가 "프로젝트 아틀라스의 2026년 9월 2일자 검토 문서를 찾아줘"를
  입력해도 과거 화면은 고정 주간보고서/이메일 시나리오를 재생했다.
- "개발팀 3명에게 이메일을 발송했습니다"는 **가짜 성공 문구**였다.
  주소 확인·첨부파일 생성·SMTP/MCP 전송·실제 발송 기록이 없다.
- 과거 'Execution 상세 보기'는 예시값 `EXE-20260902-00125`로 이동했다.
  백엔드 Execution 상세 API는 실제 UUID를 요구하므로 해당 링크는 실패한다.

## 이번 수정

1. 왼쪽 메뉴에 **Agent Run (데모)** 표기, 화면 최상단에 상시 표시되는
   **실제 분석/실행/전송 없음** 배너 추가.
2. *사전 정의된 정확히 한 문장* (주간 보고서를 생성하고 개발팀에
   이메일로 발송해줘)에서만 상태 전이 데모 시작.
   다른 문장은 **실행되지 않음**을 즉시 안내하고 단계 진행을 금지.
3. 완료 문구는 **시뮬레이션 완료, 실제 파일·메일·Execution 기록 없음**
   으로 변경. 가짜 파일/Execution ID 제거.
4. 잘못된 Execution 상세 링크는 제거하고,
   실제 `/executions` **목록으로 이동**하는 별도 안내를 제공.
   실제 목록에서 존재하는 실행 UUID를 클릭해야 상세 페이지로 이동한다.
5. 프론트엔드 단위 테스트에서 임의 지시문 거부 및 잘못된
   성공/상세 링크가 없는지 확인.

## 사용자 검증 및 한계

이번 변경은 **데모를 실제 기능으로 연결한 것이 아니라 혼동을 방지하는 수정**이다.
실제 자연어 지시문을 입력 → LLM 의도 분석 → 사용 가능한 MCP Tool 매핑 →
(필요시 승인) 실행 → 실제 UUID 기반 상세 보기의 흐름을 제공하려면
별도 UI/API 통합 작업이 필요하다.

현재 Backend는 관련 AgentRequest/Execution 인터페이스를 일부 제공하지만,
Agent Run 화면의 실제 Agent 선택·요청 생성·상태조회·MCP 실행 연동
가능 여부는 별도 설계·검증이 필요하다. 정식 실행 기능이 준비되기
전까지 화면에 실제 성공으로 보일 가상 상태·결과를 출력하면 안 된다.

참고: 기존에 제시된 L3-02 자연어 분석 평가 문장은 실제 모델 성능을
증명하는 UI 통합시험과 동등하지 않다. 평가 실행기와 사용자 화면
구동 검증은 구분해 관리한다.
